# v2.1 Design: Lightbox improvements + Mobile optimisation

**Date:** 2026-04-19
**Status:** Approved

---

## Problem

Two separate UX defects in the current frontend:

1. **Lightbox loses map state and recomputes navigation group on every prev/next.**
   Opening an image navigates to a new route (`/image/:id`), which unmounts the map and
   resets its viewport. Navigating prev/next triggers a full re-fetch and recomputation of
   the nearby group — so the group changes based on whichever image is currently shown,
   making the order unpredictable.

2. **Leaflet zoom controls are too small for mobile touch.** The default 26×26px controls
   are below the 44px minimum tap target. Everything else in the UI (modal buttons, markers,
   social share) already meets the minimum.

---

## Solution overview

Both problems are fixed in a single frontend PR:

1. **Single-page overlay (MapPage):** Merge `MainMapView` and `ImageView` into one component
   (`MapPage`) that is always mounted. The modal overlays the map; the map never unmounts.
   Map viewport and navigation group are preserved in component state.

2. **Leaflet zoom control CSS fix:** Override Leaflet's default control size to 44×44px on
   mobile, 36×36px on desktop (up from 26×26px).

---

## Architecture

### Routing — layout route pattern

```tsx
// AppRouter.tsx
<Routes>
  <Route element={<MapPage />}>
    <Route index element={null} />                    // /
    <Route path="image/:imageId" element={null} />    // /#/image/:id
  </Route>
</Routes>
```

React Router keeps `MapPage` mounted when navigating between `/` and `/image/:id` because
both paths are siblings under the same parent layout route. The map component never unmounts,
so its Leaflet viewport state is preserved naturally — no URL params, no context, no ref
tricks needed.

### MapPage — unified component

`MapPage` replaces both `MainMapView` and `ImageView`. It holds:

```ts
images: ImageRecord[]          // loaded once on mount
selectedImage: ImageRecord | null
nearbyGroup: ImageRecord[]     // locked when modal opens; cleared on close
mapRef: React.RefObject<L.Map> // for programmatic pan (deep links)
```

`MapView` is always rendered. `ImageModal` overlays it when `selectedImage` is non-null.

### State transitions

| Trigger | State change | URL |
|---|---|---|
| User clicks map marker | Set `selectedImage` + compute and lock `nearbyGroup` | `navigate('/image/' + id)` |
| Press ▶ / ◀ in modal | Update `selectedImage` within locked `nearbyGroup`; no recompute | `navigate('/image/' + nextId, { replace: true })` |
| Close modal (✕ / Esc / backdrop) | Clear `selectedImage` and `nearbyGroup` | `navigate('/')` |
| Deep link (`/#/image/abc`) | On mount: fetch images, find image, compute group, open modal, `mapRef.panTo(lat, lng)` | unchanged |

Key rule: **`nearbyGroup` is computed exactly once per modal open session.** Prev/next navigation
only updates `selectedImage` within the existing group.

## Component changes

### `MapPage.tsx` (renamed from `MainMapView.tsx`)

New responsibilities compared to `MainMapView`:
- Reads `imageId` from `useParams()` to detect deep links on mount.
- Holds `selectedImage` and `nearbyGroup` state.
- Computes `nearbyGroup` when opening a modal (image + all images within 1 km, sorted by
  distance, with the selected image first).
- Passes `onMapReady` callback to `MapView` to capture the Leaflet map instance for
  programmatic pan.
- On deep link: after images load, sets state and calls `mapRef.current.panTo(...)`.

`handleImageSelect` (called by `MapView` on marker click):
1. Find the clicked `ImageRecord` in `images`.
2. Compute `nearbyGroup` (client-side haversine, same 1 km radius as before).
3. `setSelectedImage(image)` + `setNearbyGroup(group)`.
4. `navigate('/image/' + image.id)`.

`handleNavigate` (called by `ImageModal` on prev/next):
1. Find `currentIndex` in `nearbyGroup`.
2. Advance index (wraps around).
3. `setSelectedImage(nearbyGroup[nextIndex])`.
4. `navigate('/image/' + nextId, { replace: true })`.

`handleCloseModal`:
1. `setSelectedImage(null)` + `setNearbyGroup([])`.
2. `navigate('/')`.
3. Map viewport: unchanged (MapView still mounted).

### `MapView.tsx`

Add `onMapReady?: (map: L.Map) => void` prop. Implement via a child component that calls
`useMap()` (required because react-leaflet's `useMap` hook must be used inside
`<MapContainer>`):

```tsx
const MapReadyCapture: React.FC<{ onReady?: (map: L.Map) => void }> = ({ onReady }) => {
  const map = useMap();
  useEffect(() => { onReady?.(map); }, [map, onReady]);
  return null;
};
```

Remove the existing "pan to selected image" side-effect that currently calls
`map.setView(...)` on `selectedImageId` change — this is now handled by `MapPage` via
`mapRef` for deep links only. Regular marker clicks don't pan because the modal opens
immediately and the map position is already correct.

### `ImageView.tsx`

**Deleted.** All logic moves to `MapPage`.

### `AppRouter.tsx`

Replace the two separate `<Route>` elements with the layout route pattern shown above.
Update the import (rename `MainMapView` → `MapPage`).

### `ImageModal.tsx` + `ImageModal.css`

No logic changes. The component interface (`image`, `nearbyImages`, `isOpen`, `onClose`,
`onNavigate`) stays the same.

Minor CSS tweak: reduce metadata padding on screens shorter than 600px to prevent the image
from being squeezed on devices like iPhone SE.

## Mobile CSS fix

Add to `MapContainer.css` (or a global Leaflet override block):

```css
/* Leaflet zoom controls — increase touch target from default 26px */
.leaflet-control-zoom a {
  width: 36px;
  height: 36px;
  line-height: 36px;
  font-size: 18px;
}

@media (max-width: 768px) {
  .leaflet-control-zoom a {
    width: 44px;
    height: 44px;
    line-height: 44px;
  }
}
```

Add to `ImageModal.css`:

```css
/* Prevent metadata from squeezing image on very short screens */
@media (max-height: 600px) and (orientation: portrait) {
  .image-metadata {
    padding: 8px 12px;
    font-size: 11px;
  }
  .image-title {
    font-size: 13px;
    margin-bottom: 4px;
  }
}
```

## Testing

Existing tests are unaffected (they test `ApiClient` and utilities, not route components).

Manual regression checklist:
- [ ] Click a marker → modal opens, map stays in place
- [ ] Press ▶ three times → group doesn't change, wraps around
- [ ] Press ✕ → map is at same position as before opening
- [ ] Keyboard arrow keys and Esc work
- [ ] Touch swipe left/right navigates prev/next
- [ ] Shared link (`/#/image/:id`) → map centers on image, modal opens
- [ ] Leaflet zoom +/− tappable on mobile (≥ 44px)
- [ ] iPhone SE portrait: modal not overflowing
